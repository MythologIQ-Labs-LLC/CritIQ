# CritIQ Documentation Map

Use these documents as the current product authority:

1. `CONCEPT.md` - product boundary and complete local feature set.
2. `FEATURE_MATRIX.md` - authoritative feature checklist.
3. `ARCHITECTURE_PLAN.md` - active implementation and data contracts.
4. `ACCEPTANCE_TEST.md` - complete desktop release-candidate test.
5. `BACKLOG.md` - live blockers and unscheduled boundary-expansion ideas.
6. `ONE_DAY_EVOLUTION.md` - implementation evolution and completion record.

## Historical governance records

The following files are preserved as historical evidence and must not be treated as descriptions of the current source tree or dependency graph:

- `SYSTEM_STATE.md`
- `META_LEDGER.md`
- `SHADOW_GENOME.md`
- `SUBSTANTIATION_REPORT.md`
- `SUBSTANTIATION_FAILURE.md`
- `BOOTSTRAP_REPORT.md`
- `Planning/plan-razor-remediation.md`

Some of those sealed records describe the March 2026 repository state, including modules and dependencies that have since been removed. They remain useful as audit history, not as active architecture documentation.
